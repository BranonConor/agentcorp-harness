# HappyMachines technical reference

HappyMachines is a local, single-user spatial Copilot SDK harness built on the **original AgentCorp 3D office**: its room geometry, procedural pixel art, shaders, lighting/day cycle, desks, camera controls, activity chrome, and sprite movement. The one-line 16x16 pixel `;D` badge is shared by the HUD, HQ sign, and favicon. Its rounded solid background is dark blue-green with light glyphs in the light app theme, and light neutral with dark glyphs in the dark app theme; it has no halo or shadow. The HUD wordmark and sign text are also generated from pixel art. The sign renderer accepts only short, locally supplied ASCII text and a predefined mark (there is no user-facing sign configuration). Click **+ above an empty desk** (or **Add agent**) to create an independent SDK session and sprite; click a sprite to focus the camera and open its persistent chat. SDK events drive speech, working, idle, and permission states. This does not attach to existing Copilot app sessions.

Agents return to their desks when a chat starts and remain seated there while working, waiting for permission, or for the first two full minutes after becoming idle. A small in-world idle symbol marks an idle desk without showing chat or permission content. Only after two minutes of continuous idle do they move toward the coffee counter or lounge; new activity brings them back to their desks. The idle start time persists across roster updates and reloads.

## Install and run

Requires Git, Node.js 22.12+ (or 20.19+), npm, and a WebGL-capable browser. The default Copilot account profile requires an installed Copilot CLI and CLI sign-in: follow the [official Copilot SDK setup guide](https://github.com/github/copilot-sdk/blob/main/docs/getting-started.md) and run `copilot login` if necessary. There is **no in-app OAuth**. BYOM profiles use the bundled SDK runtime without requiring Copilot sign-in; the selected endpoint must be reachable from this machine and support the model's required streaming/tool-call capabilities.

```sh
git clone https://github.com/BranonConor/happymachines.git
cd happymachines
npm install
npm run dev -- --workspace ./sandbox
```

Choose a **new, dedicated scratch directory** for `--workspace`, not an existing checkout or your Copilot home. Keep `.local/` and the workspace out of version control; the defaults above are gitignored. For a Copilot account, sign in through the CLI before starting; for BYOM, start the server and expand **Manage → Overview → Model provider → Add a model profile or see provider details**, entering only the *name* of a credential environment variable configured securely in the server process. The local Ollama endpoint is the default keyless BYOM option. `gh auth login` is separately needed for private GitHub repository access and verified merged-PR rewards. Brave search is optional, configured below. Do not paste credentials into chat, profile fields, tracked files or shell commands that remain in history.

**Optional agent web search:** The installed SDK 1.0.15 (bundled CLI 1.0.89) defines a progress event for hosted `web_search`, but that is not an agent-callable tool or evidence that it works for both Copilot-auth and BYOM sessions. The exposed `BuiltInTools.Isolated` set contains no web search, and the SDK has no documented provider-independent native search configuration. `web_fetch` retrieves a known URL; it is not web search. Do not infer that a hosted search event enables a reliable keyless search capability. For a no-*personal-API-key* deployment, consider a deliberately configured self-hosted SearXNG instance, a Bing search provider account managed by your organization, or a Copilot-hosted search tool only if your authenticated model/session explicitly offers it (not assumed for BYOM); none is configured automatically here. This office instead offers an opt-in `search_web` custom tool backed by the [Brave Search Web API](https://api-dashboard.search.brave.com/app/documentation/web-search/get-started). Obtain your own Brave API key, set `AGENTCORP_SEARCH_PROVIDER=brave` and `AGENTCORP_BRAVE_API_KEY` in the server process environment using your secret manager (not in chat, commands saved in shell history, or committed files), then run `npm run dev -- --workspace ./sandbox`. Restart after changing the configuration. Without both variables, the tool is absent and each agent's chat reports the provider-specific reason; the local `/api/search-capability` status never exposes the key. An unknown provider name fails at startup instead of silently disabling search.

**Privacy and limits:** When enabled, agents can initiate searches without a separate permission prompt; **each query leaves your device for Brave**, may be billed to your Brave API account, and is also part of the agent's SDK tool-call history. Do not search for secrets. Search returns at most five public results with source URL, title, snippet and a page date only if the provider supplies a parseable one (`null` otherwise). It does not fetch the resulting pages or guarantee accuracy. The adapter limits queries to 200 characters, throttles to one request every two seconds across all agents, caps usage at 50 requests per server run, times out at eight seconds and caps responses at 256 KiB; provider/network/schema errors are explicit. The API key is sent only as a header to Brave, never embedded in prompts, results or capability responses. Built-in shell/write/repository permission decisions are unchanged. Search availability for BYOM and Copilot sessions depends on this independent Brave configuration, not hosted Copilot web search.

**Model onboarding:** In **Manage → Overview → Model provider**, expand **Add a model profile or see provider details** to add an immutable, named Copilot account model, OpenAI-compatible HTTPS, Anthropic HTTPS, Azure HTTPS or local Ollama profile. Set an API credential in the server process environment (for example `MY_PROVIDER_API_KEY` via your secret manager), then enter **only its environment variable name** in the form. Ollama's loopback HTTP endpoint needs no key by default (`http://127.0.0.1:11434/v1`). Remote endpoints must use HTTPS and cannot include URL credentials or query parameters. Enter the provider's model ID, optional wire model/deployment, wire API for OpenAI/Azure, optional Azure API version, token limits and supported vision/reasoning capabilities; not all models support streaming/tool calls. The Copilot model-list button requires Copilot login and reports listing errors explicitly. Select a default profile for **new agents**; an existing agent switches only via **New assignment**, where the model profile is selected before a new SDK session starts. Assignment history records the exact nonsecret profile snapshot and retains previous transcripts. Profiles cannot be changed or removed after creation, so restarts use the original provider/model or fail explicitly when its referenced environment variable is missing or its profile changed. The saved state and browser API contain nonsecret profile settings only. External providers receive prompt/context/tool content; configure one you trust, and review all permission prompts. Copilot CLI sign-in and optional `gh auth login` for private GitHub repositories are independent.

`./sandbox` is the explicitly selected, dedicated scratch root. It must be initially empty or already marked by this app; the backend creates and marks it on first use. You can pass a different new absolute path with `--workspace`; if you choose another directory *inside this repository*, add it to your local Git exclude file so tool output is not committed. **Do not choose a home directory or an existing work repository.** Start the browser at the printed URL, normally **http://127.0.0.1:4173**. The browser must be on the same machine. `npm run dev` rebuilds the frontend; restart it after UI changes. `npm start -- --workspace ./sandbox` serves the already-built frontend. Set `--port 4173` to change the port; `--state .local/other-state.json` allows an isolated test room.

In the office, all 16 desks are visible: click **+** above an empty desk, use the header **Add agent**, or use **Manage → Agents → Add agent** when the list is empty. All three create the same independent SDK agent; plain floor clicks do not. A new agent opens **NEW HIRE → Configure this agent**: name it, enter a working style or instructions, optionally assign read access to verified projects, then **Save & start chat**. Closing setup retains the agent and its files; selecting it again resumes setup. The pencil **Edit agent** button opens profile editing; Back returns to the same conversation without replacing its SDK session. Saved instructions affect the next job/chat, not the current conversation; the optional preview compares them. The cosmetic profile rank is preserved on save but is no longer editable; career rank remains earned through progression. Click a pixel sprite or choose an agent in **Manage → Agents** to open its conversation. Conversation **Options → Agent settings & more options** holds profile, curated notes, career, project access and assignment history; the settings disclosure reveals actions including **New assignment**. Back or Escape returns to conversation, while Back from conversation returns to the agent list; Close dismisses the panel. Urgent permission and repository requests remain in the conversation, not settings. Each active agent has a distinct sprite and matching portrait; agent messages display that portrait above the bubble, separate from user messages. Names remain unique after firing and looks survive reload/archive. An empty chat displays a local greeting, not a saved SDK reply. Chat starts at the latest message, follows streaming replies near the bottom, and respects manual scroll-up. While an agent responds without streamed text, a reduced-motion-aware thinking indicator appears without adding an empty message bubble. Replies and list previews render safe GitHub-flavored Markdown; hover/focus (or touch) the overlaid copy icon to copy raw Markdown. Enter sends, Shift+Enter adds a newline, and **Stop** aborts a turn including pending access requests. Tool permission prompts in the default manual mode require individual **Allow once** or **Deny** decisions. The Manage attention badge and agent row reveal pending reviews; the lower-left banner shows connection and working/idle/attention counts.

Configure projects in **Manage agents → Overview → Global project access**: choose **Assign projects globally**, look up a name/owner on GitHub, select the exact verified repository and explicitly **Share read with all agents**. New projects added there start globally readable; turn **Global read** off to retain one only in the catalog. **Eligible for task worktrees** is a separate global write-eligibility toggle, off by default. In **Agent settings → More options → Assign projects**, the chooser offers either durable **Read for this agent** or **Eligible for task worktree** (write eligibility includes read). Direct agent projects appear before office-shared projects; **Remove agent access** removes direct grants, **Exclude agent** blocks global inheritance, and **Restore global read** clears the exclusion. Each row reflects effective access. Write eligibility does not enter a worktree or approve tools: choose **Review Edit worktree for this task**, verify the project again and explicitly approve **Edit worktree** in that agent's chat. Configuration and opening the card never clone the repository; the edit assignment belongs only to the current SDK task/session. A verified snapshot is cloned on the first authorized research or edit approval if not already cached. Only canonical GitHub owner/repo, clone URL, default branch and privacy metadata from a verified lookup may become a policy; pasted paths and unverified identities are not accepted. Built-in tools need individual approval by default, even after a read grant. A worktree is not an OS sandbox.

Ask an office agent to research or edit a GitHub repository. Its SDK **request_repository_access** tool sends a name/owner hint, purpose and intended read/edit scope. The agent asks conversationally **in its own message bubble**, with compact scope buttons and verified owner/repo, GitHub source, public/private status and branch. **Access details** expands the clone URL, cache behavior and safety limits when needed. For ambiguous names choose the exact repository; **Wrong repo?** lets you correct the hint without entering a local path. Choose **Deny**, **Read this task**, **Read this session**, **Read for persona** (default durable choice), **Read for office**, or—only if editing was requested—**Edit worktree**. Deny does not clone/fetch. Approval automatically makes a shallow clone of the remote default branch under ignored `.local/repos/`; it does **not** include local unpushed commits or working changes in another checkout. Short names resolve under the GitHub owner of this harness's `origin`; use `owner/repo` to specify another owner. If the model only reports the repo unavailable without calling its tool, open that agent's **⋯** menu in the chat header and select **Find a GitHub repository…**. The agent cannot select a local path, grant itself access or add another office agent; use a desk + for the latter.

Public repository metadata and clone use GitHub HTTPS without requiring `gh`. A private repository metadata lookup and clone may require an authenticated GitHub CLI (`gh auth login`) with that repository's access; failed lookups show an actionable sign-in/network error and grant nothing. The app does not collect credentials, scan local checkouts or import Copilot app projects. A candidate reporting more than 100,000 KiB is rejected before clone; clone also has a two-minute timeout. A verified cached snapshot of the same remote branch is reused for up to six hours; afterward approval creates a new shallow clone. You can select **Fetch fresh snapshot** on the card to bypass a younger cache. A changed/dirty cache is refused rather than silently reused, and previous snapshots are preserved for inspection. GitHub metadata lookup occurs to show the candidate before approval; cloning/fetching only happens afterward.

Read approval gives the bounded **research_attached_repository** tool for listing and reading tracked, non-ignored, non-hidden, non-secret-like regular text files up to 64 KiB; untracked files, symlinks, likely secret paths, and binaries are excluded. Each call must name the exact `owner/repo` and rechecks effective access before and after reading, including during a running turn; policy revocation prevents stale results. Task approval lasts until that SDK turn ends (or, when granted outside a turn via the header menu, through the next turn). Session approval survives restart/archive/restore for that assignment; persona read survives subsequent assignments. Office read extends to all personas except those excluded explicitly. The access request itself expires after 90 seconds without a human decision; **90 seconds is not the grant lifetime**. Read files may still contain unexpected sensitive content; inspect the selected repository first. SDK built-in shell, write, view and unknown tool permissions still need **individual Allow once/Deny** review unless trusted-local autonomy is explicitly enabled for that edit assignment; unknown tools continue to prompt.

**Edit in a separate worktree** creates a uniquely named `agentcorp/<agent-id>/<uuid>` branch at the approved cloned snapshot's `HEAD` and a Git worktree under this harness's ignored `.local/worktrees/`. The SDK changes **the same agent session ID's** working directory to that worktree; the primary checkout is not used as the working directory, and its unpushed/uncommitted changes are not included. Subsequent reads through the custom tool use tracked files in that worktree. **This is not OS isolation:** a shell command or tool may access anything your local account can, including files and credentials outside this repo. Do not interpret GitHub project eligibility, command text, parsed command lists, or worktree paths as confinement.

**Trusted-local autonomy (optional):** After explicitly approving an eligible edit worktree for a particular agent's assignment, its task card offers **Allow autonomous local work for this task**. It is **off by default**; manual Allow once/Deny remains in force until you choose it. With consent, the server autoapproves only matching built-in `bash`, `apply_patch`, `view`, `rg`, and `glob` permission requests for that agent, assignment, SDK session and selected worktree, and records each decision in the assignment transcript. It does not inspect shell strings to decide safety. Managed-policy requests, sandbox-bypass requests, unknown or mismatched tools, MCP/custom/network tools and permission requests lacking matching tool-call provenance continue through the existing review policy. The agent can still run subprocesses and access external paths and network via an approved shell command. Keep the browser open; you can **Turn off autonomous local work** during a turn (already running commands cannot be undone). Consent survives subsequent prompts in the same active assignment, but ends on worktree change, revoke, stop, archive, fire, new assignment, last browser disconnect or server restart. The server does not persist consent, even though it preserves the worktree and transcript. SDK 1.0.15 / CLI 1.0.89 exposes experimental sandbox RPC policy, but this app does not claim or enable a verified OS sandbox. [CLI local sandbox defaults](https://docs.github.com/en/copilot/how-tos/cloud-and-local-sandboxes/configuring-local-sandbox-settings) are separate from this consent. A future truly confined mode would require separately verified sandbox controls.

The original scratch directory and conversation are retained; restart resumes the worktree path in manual mode. Removing configured write eligibility stops affected active turns, denies pending tool decisions and returns those assignments to scratch; an already-executing command cannot be retroactively contained. **Revoke** also moves the SDK working directory back to scratch while leaving the worktree/branch and all edits intact. Archive and Send home also **never remove worktrees or cached clones**. The Overview lists every worktree this room created for manual inspection/cleanup; resolve and merge its edits yourself. Git checkout may honor repository filters/configuration, so select only repositories you trust. **Legacy absolute-path grants remain recorded and revocable; they are not silently moved into the new cache.**

Each agent row's **⋮** menu offers **Move desk…** (pick an empty desk or confirm an occupied-desk swap, without interrupting either agent's task), **Archive** (pause that agent's SDK connection, free its desk and remove its sprite while preserving its SDK session, transcript and scratch files) and **Restore to office…** (choose an empty desk; the former desk is marked if free). The header Add agent button also opens the desk chooser; the in-world + creates directly at its empty desk. Desk assignments use the existing persistent `deskIndex` and `lastDeskIndex` fields; a stale occupant or occupied restore target is refused, never silently reassigned. Archived agents remain in the Agents list with read-only chat until restored. A full office cannot restore another agent until a desk is freed. **Fire permanently…** requires explicit confirmation and retention choice; local persona and assignment history and all scratch/worktree files remain. There is no automatic cleanup of working files or branches. Archive and fire are blocked while a turn or permission decision is pending; SDK deletion errors leave the agent record visible and report the failure. Reload the browser or restart the backend with the same `--workspace` to recover active and archived conversations. Keep the browser open while awaiting a permission decision. Asking an existing agent to add an agent is **not** the same as clicking +: this prototype has no chat tool for creating office workers.

The **persona** (immutable ID, unique display name, portrait/art ID, editable behavior instructions, working style, specialties, cosmetic title, preserved legacy rank, explicit project read policies and user-approved notes with provenance) persists separately from an **assignment** (SDK session ID, transcript, repository grant, scratch workspace, start/end, outcome, and a snapshot of persona guidance). New personas must complete setup with instructions or a working style before chatting; closing setup preserves the incomplete persona and its session for later. Completing setup applies the chosen guidance to that *unused* SDK session under the same identity. Existing personas migrate as already set up; pre-migration assignments retain their original empty guidance on resume. Subsequent profile/note edits take effect **on the next assignment**, not midway through the current SDK conversation, and the inspector can preview both the active snapshot and the next one. Each snapshot is bounded: instructions use at most 600 characters, working style the first 280, specialties the first eight (50 characters each), and the eight most recent approved notes (240 characters each, with 80 characters of source). Notes and their sources are quoted lower-trust reference material, not a new permission channel. No previous transcript is compiled into the prompt. User profile text does not override SDK safety policy, repository grants, or individual tool permission prompts; title/rank and promotions remain cosmetic. Notes require a deliberate user action (up to 12 stored notes, 500 characters per new note and 160 per source). **New assignment** is available only after the current turn finishes; it preserves the prior transcript and worktree as historical data, creates a fresh SDK session and scratch folder, and starts without a task/session/edit grant; inherited office and direct persona read still apply. A persona can return to its desk with its new assignment, while completed assignments remain inspectable. **Fire** requires explicit confirmation and a retention choice: keep the SDK session, or delete only the current SDK session. Both choices retain local persona/assignment history and **never delete scratch files, Git worktrees, clones or user files**; SDK deletion cannot be undone. Legacy Send home API remains for compatibility and corresponds to the delete-SDK choice.

**Career and office upgrades:** A completed assignment earns **20 XP + 8 credits** only after you inspect its recorded user prompt and assistant response, enter outcome evidence, choose a specialty and explicitly confirm it. A completed manual review earns **10 XP + 4 credits** only for a participant with a recorded response and your confirmation. An attributed **merged GitHub PR earns 30 XP + 12 credits** only when its assignment records a verified repository, you explicitly attribute the PR and the server's authenticated `gh api` call confirms its merged state, repository identity and merge SHA. The PR must have merged after the assignment began; an assignment can earn either its outcome reward or one PR reward, not both. GitHub verification requires working `gh` authentication and repository visibility (including access to private repositories); unavailable authentication or an API failure is an explicit error, **not** a user-confirmed substitute. Existing completion labels, auto-generated responses, meeting turn counts, tokens, model calls, failed tests and model/provider choice never award anything. There is a limit of three rewards per persona per UTC day; a deterministic source ID prevents repeats across restarts and different personas. Persona career XP and specialty XP come only from ledger entries. At 40/100/200 XP, a user may explicitly promote to Specialist/Senior/Principal; these earned titles are separate from editable profile titles and never change permissions or models.

Open **Manage → Overview → Store** to see ledger-derived credits and preview **Window garden (12)**, **Lounge rug (18)** and **Desk lanterns (24)** before explicit purchase. The Store back button or Escape returns to Overview. Upgrades appear only in this app's 3D scene, do not affect agent access or performance, cannot be purchased twice and cannot overdraw the balance. Purchased decor and the outcome/promotion history persist across restarts, including for retired agents. SDK usage appears separately as aggregate reported token/model-call counts with measurement coverage and freshness; **tokens are not currency or a monetary estimate**. Historical sessions not in the recorded agent roster are outside that SDK usage snapshot.

**Meeting/review handoffs:** Open **Meetings** in Manage agents to choose 2–4 available active agents, an agenda, an optional explicit excerpt or diff (required for reviews), an optional source `owner/repo`, and a cap of 1–8 SDK turns. Only one handoff runs at a time. Click **Approve next turn** for each participant in order; the current turn must finish before the next. The recipient receives the agenda, initially shared material, and only the excerpt **you enter for that turn**. Prior replies and entire transcripts are never automatically forwarded. When using repository material, enter its source: every participant must already have effective read access, checked again before each turn; the handoff never grants access. Meeting turns reject all tool permission requests, including repository research and shell/write; no approval is inherited. Responses are recorded as bounded meeting results, and **Finish** saves your decision summary and owner tasks linked to their recorded assignments. Cancel stops an in-flight SDK turn; failures, timeouts, and restart retain partial results but require finishing or cancelling rather than silently retrying. Agents' existing SDK sessions retain previous private context, so this is a **human-approved handoff, not an isolated clean-room review**: do not use it where the reviewer must be technically unable to recall previously seen material. Text you paste without a source cannot be proven repository-free; disclose the source whenever it contains repository material. The turn cap counts dispatched messages, not tokens or money.

The HUD uses flat warm beige/ink colors by default and a flat deep blue-green dark palette when the system prefers dark appearance. The header theme button overrides the system preference and remembers the choice in local browser storage; neither theme changes the office's original art or daylight cycle. SDK Online/Connecting/Offline/Error stays in the same fixed lower-left banner as agent working/idle/attention counts; click it to open **Manage agents → Overview**; an **SDK needs attention** message and retry button appear there only when disconnected, alongside provider onboarding. **Refresh SDK usage** queries the SDK's experimental `session.rpc.usage.getMetrics()` for each recorded active and archived session **on demand**, showing accumulated token/model-call and per-session changed-file counts with a last-refreshed time; SDK failures explicitly mark partial or unavailable data rather than filling in invented zeros. Distinct-file counts can overlap between sessions and are not an office-wide unique-file count or a cost estimate. There is no projected SDK plaque, persistent Signals widget, metrics strip or workspace strip.

Use `npm run typecheck`, `npm test`, and `npm run build` to validate the app.

The Manage UI's shared controls live in `agent-inc-live/src/controls.tsx` with theme-aware styles in `agent-inc-live/controls.css`. `SelectField` takes a visible `label`, controlled string/number `value`, `options` (`{ value, label, disabled? }`) and `onValueChange`, plus optional native form `name`, `required`, `disabled`, `readOnly` and `id`; its Base UI popup is portaled into `.live-shell` to retain theme colors outside the scrolling side panel. `Toggle` uses controlled `checked`/`onCheckedChange`, an accessible `label`, and optional form `name`, `disabled` and `readOnly`. `Disclosure.Root`, `.Trigger` and `.Panel` wrap Base UI Collapsible; panels use `ui-disclosure-panel` for reduced-motion-aware height transitions. Multi-select participants and explicit outcome confirmation remain native checkboxes rather than switches.

## Safety and recovery

HTTP is bound to `127.0.0.1` with loopback host, same-origin write, and local browser-cookie checks; do not expose it through a proxy. Built-in SDK permission requests require **Allow once** or **Deny** in manual mode; trusted-local consent only changes the enumerated built-in routine tools for one current edit assignment and is never persisted. The separately attached read-only research tool needs no additional per-file approval once the user explicitly grants that specific repo to that agent. Outstanding human permission requests are denied when the last browser leaves or after 90 seconds. A working directory (even a separate Git worktree) and an instruction to the model are **not OS isolation**: a permitted built-in tool can reach outside its folder.

Each agent has its own SDK session ID, transcript, desk (or archived state), status, pending permission, persona and recorded working directory in ignored `.local/state.json`; the SDK also stores session history under the user's Copilot home. Explicitly approved repo roots, cloned snapshot metadata and created worktree locations are stored locally; request prompts and task grants are invalidated on restart. Existing v2 assignments acquire the original `copilot` profile on first load without replacing their IDs or transcripts. The original single-agent state is migrated in place, keeping its session ID, transcript and root `./sandbox` working directory. In a fresh room, all agents use distinct disposable `./sandbox/agents/<agent-id>/` scratch folders. Copilot account prompts go to the GitHub Copilot service; BYOM prompts go to the selected endpoint. There is no private app RPC, terminal scraping, hosted backend, or analytics added by this app. A restart resumes **each active SDK session** with its recorded profile in its own scratch directory or explicitly approved worktree; archived sessions remain recorded but disconnected until restored. An interrupted turn is labeled interrupted, and a failed resume leaves that agent's transcript visible with Retry agent connection rather than silently replacing it. The SDK may not persist an *empty, never-messaged* session; if it reports that exact session missing, the app reinitializes only that empty session under the same ID and says so in the UI. A session containing any messages is never silently replaced.

State uses a **versioned atomic JSON store (schema 6)** rather than SQLite. Migration from unversioned state creates `.local/state.json.v1.bak`; migration from v2, v3, v4 or v5 creates the corresponding `.v2.bak`, `.v3.bak`, `.v4.bak` or `.v5.bak` before replacement. Backups are never overwritten; invalid/unknown versions and malformed reward ledgers are refused. Writes serialize in process, flush a private temporary file and atomically rename it, then sync the directory. To roll back, stop the server, preserve the newer state elsewhere, restore the matching backup to the chosen state path and run the older release; subsequent edits cannot be automatically backported. Do not run two servers against the same state path. The JSON layout has `projects[]` for verified identity and office sharing, `personas[].repositoryPolicies` for durable individual read/exclusion, `assignments[]` for session history and linked follow-ups, `meetings[]` for bounded handoffs, `progression[]` for append-only rewards, promotions and purchases, and `agents[]` as the current desk/runtime projection. Balances, earned specialties and ranks are replayed from the ledger, not separately editable counters. Existing IDs, names, sessions, messages, desk positions, memories, grants and worktree records are carried forward. V2 remote grants become explicit persona policies; legacy local-path grants remain recorded in assignment history but **cannot authorize the research tool** until a GitHub project is verified. No history is injected into new SDK sessions.

This harness has at most **16 active agents**, one per available office desk; archived agents do not occupy desks. Once all are occupied, Add agent clearly says **Office full (16 desks)**, while all existing conversations remain usable. This is not general multi-agent collaboration: shared read policy does not share shell/write authority or coordinate tasks, and agents do not spawn other office agents by chat. SDK sessions created by this app are independent; this app **does not connect to, control, observe or infer parent/child relationships among existing Copilot app/CLI sessions**. Automated handoff/merge, worker spawning from chat, account switching, and remote hosting are not implemented. If session creation fails after preparing a scratch folder, the unused marked folder is left untouched for manual inspection rather than deleted.

## Original scene provenance

With the repository owner's explicit permission, the scene was ported from [BranonConor/agentcorp](https://github.com/BranonConor/agentcorp) at commit `724d9031530c81618bf32007fbaa17ac412af7a2`. The copied `agent-inc/game/{animation,lighting,live-layout,simulation,sprite-art,world}.ts`, `agent-inc/app/styles.css`, `agent-inc-live/src/office.tsx`, `agent-inc-live/src/room.ts`, and `agent-inc-live/live.css` originate there. The simulation, art, lighting, layout, room projection, and original styles are reused; `world.ts` adds empty-space selection and `office.tsx` replaces the read-only extension feed with this app's SDK backend and chat. `agent-inc-live/sdk-chat.css` contains the additional conversation/permission UI styling. The original browser extension (`.github/extensions/agent-inc-live`) and its session-activity data source are **not** installed or copied into this app; this app's on-demand usage comes from its own SDK sessions, not the original extension's activity feed. The room remains the original renderer, not an approximation.
