# AgentCorp SDK office

A local, single-user spatial Copilot SDK prototype using the **actual AgentCorp 3D office**: its original room geometry, procedural pixel art, shaders, lighting/day cycle, desks, camera controls, activity chrome, and sprite movement. Click **+ above an empty desk** (or **Add agent**) to create an independent SDK session and sprite; click a sprite to focus the camera and open its persistent chat. SDK events drive speech, working, idle, and permission states. This does not attach to existing Copilot app sessions.

## Install and run

Requires Node.js 22.12+ (or 20.19+), npm, a WebGL-capable browser, and an authenticated GitHub Copilot CLI account. Follow the [official Copilot SDK setup guide](https://github.com/github/copilot-sdk/blob/main/docs/getting-started.md) for CLI installation, then run `copilot login` if necessary; the app uses that sign-in and never collects credentials.

```sh
npm install
npm run dev -- --workspace ./sandbox
```

`./sandbox` is the explicitly selected, dedicated scratch root. It must be initially empty or already marked by this app; the backend creates and marks it on first use. You can pass a different new absolute path with `--workspace`; if you choose another directory *inside this repository*, add it to your local Git exclude file so tool output is not committed. **Do not choose a home directory or an existing work repository.** Start the browser at the printed URL, normally **http://127.0.0.1:4173**. The browser must be on the same machine. `npm run dev` rebuilds the frontend; restart it after UI changes. `npm start -- --workspace ./sandbox` serves the already-built frontend. Set `--port 4173` to change the port; `--state .local/other-state.json` allows an isolated test room.

In the office, all 16 desks are visible: **click + above an empty desk** (or **Add agent**) to create a new independent SDK session; plain floor clicks do not create agents. **Click a pixel sprite**, or open **Manage agents → Agents** and choose an agent, to focus the camera and open that same agent's dedicated chat. Back returns to the agent list; Close dismisses the panel; Escape goes back or closes it. Each concurrently active agent has a different procedural pixel sprite and a matching face portrait in the list; names/looks survive reload and archive. If a new occupant takes an archived agent's look, restoring the archived agent requires archiving that occupant first. Sprite hover and keyboard focus show its name *above* the sprite; the focused agent's label stays visible until focus clears. Chat starts at the latest message, follows streaming replies while near the bottom, and respects manual scroll-up. Replies render safe GitHub-flavored Markdown (without raw HTML or unsafe links); hover/focus (or touch) the icon floating over the **bottom-right of assistant** or **bottom-left of your** bubble to copy its raw Markdown. Send with Enter (Shift+Enter inserts a newline), and use **Stop** to abort the current SDK turn, including pending access requests. When a built-in tool asks permission, inspect its full path or command and choose **Allow once** or **Deny** for *that agent*. The Manage agents attention badge and the owning agent's row make pending reviews discoverable. The fixed lower-left banner combines SDK connection state and real working, idle, and attention counts.

Ask an office agent to research or edit a GitHub repository. Its SDK **request_repository_access** tool sends a name/owner hint, purpose and intended read/edit scope. The agent asks conversationally **in its own message bubble**, with compact scope buttons and verified owner/repo, GitHub source, public/private status and branch. **Access details** expands the clone URL, cache behavior and safety limits when needed. For ambiguous names choose the exact repository; **Wrong repo?** lets you correct the hint without entering a local path. Choose **Deny**, **Read this task**, **Read this session**, or—only if editing was requested—**Edit worktree**. Deny does not clone/fetch. Approval automatically makes a shallow clone of the remote default branch under ignored `.local/repos/`; it does **not** include local unpushed commits or working changes in another checkout. Short names resolve under the GitHub owner of this harness's `origin`; use `owner/repo` to specify another owner. If the model only reports the repo unavailable without calling its tool, open that agent's **⋯** menu in the chat header and select **Find a GitHub repository…**. The agent cannot select a local path, grant itself access or add another office agent; use a desk + for the latter.

Public repository metadata and clone use GitHub HTTPS without requiring `gh`. A private repository metadata lookup and clone may require an authenticated GitHub CLI (`gh auth login`) with that repository's access; failed lookups show an actionable sign-in/network error and grant nothing. The app does not collect credentials, scan local checkouts or import Copilot app projects. A candidate reporting more than 100,000 KiB is rejected before clone; clone also has a two-minute timeout. A verified cached snapshot of the same remote branch is reused for up to six hours; afterward approval creates a new shallow clone. You can select **Fetch fresh snapshot** on the card to bypass a younger cache. A changed/dirty cache is refused rather than silently reused, and previous snapshots are preserved for inspection. GitHub metadata lookup occurs to show the candidate before approval; cloning/fetching only happens afterward.

Read approval gives *only that agent* the bounded **research_attached_repository** tool for listing and reading tracked, non-ignored, non-hidden, non-secret-like regular text files up to 64 KiB; untracked files, symlinks, likely secret paths, and binaries are excluded. Task approval lasts until that SDK turn ends (or, when granted outside a turn via the header menu, through the next turn). Session approval survives restart/archive/restore until **Revoke access** in that agent's **⋯** header menu or Send home. Granted paths and worktree branches live in that menu, not a chat footer. The access request itself expires after 90 seconds without a human decision; **90 seconds is not the grant lifetime**. Read files may still contain unexpected sensitive content; inspect the selected repository first. Every SDK built-in shell, write, view and unknown tool permission still needs **individual Allow once/Deny** review, even after a read grant.

**Edit in isolated worktree** creates a uniquely named `agentcorp/<agent-id>/<uuid>` branch at the approved cloned snapshot's `HEAD` and a separate Git worktree under this harness's ignored `.local/worktrees/`. The SDK changes **the same agent session ID's** working directory to that worktree; the primary checkout is never touched, and its unpushed/uncommitted changes are not included. Subsequent reads through the custom tool use tracked files in that worktree. Shell and write permissions are **not** auto-approved or guaranteed path-contained: a Git worktree is not an OS sandbox, so inspect every command/path and deny anything outside the authorized worktree. The original scratch directory and conversation are retained; restart resumes the worktree path. **Revoke** moves the SDK working directory back to scratch while leaving the worktree/branch and all edits intact. Archive and Send home also **never remove worktrees or cached clones**. The Overview lists every worktree this room created for manual inspection/cleanup; resolve and merge its edits yourself. Git checkout may honor repository filters/configuration, so select only repositories you trust. **Legacy absolute-path grants remain recorded and revocable; they are not silently moved into the new cache.**

Each agent row's **⋮** menu offers **Archive** (pause that agent's SDK connection, free its desk and remove its sprite while preserving its SDK session, transcript and scratch files) and **Restore** (resume the same session on its former desk if free, otherwise another free desk). Archived agents remain in the Agents list with read-only chat until restored. A full office cannot restore another agent until a desk is freed. **Send home permanently…** requires a second explicit confirmation; it deletes exactly that agent's SDK session and local conversation/record, but **keeps all its scratch/worktree files untouched** for recovery—even for the original root-sandbox agent. There is no automatic cleanup of working files or branches. Archive and send-home are blocked while a turn or permission decision is pending; SDK deletion errors leave the agent record visible and report the failure. Reload the browser or restart the backend with the same `--workspace` to recover active and archived conversations. Keep the browser open while awaiting a permission decision. Asking an existing agent to add an agent is **not** the same as clicking +: this prototype has no chat tool for creating office workers.

The HUD uses flat warm beige/ink colors by default and a flat deep blue-green dark palette when the system prefers dark appearance. The header theme button overrides the system preference and remembers the choice in local browser storage; neither theme changes the office's original art or daylight cycle. SDK Online/Connecting/Offline/Error stays in the same fixed lower-left banner as agent working/idle/attention counts; click it for **Manage agents → Overview** connection details/retry. Overview's **Refresh SDK usage** queries the SDK's experimental `session.rpc.usage.getMetrics()` for each recorded active and archived session **on demand**, shows accumulated token/model-call and per-session changed-file counts, earliest session start and measured/total coverage; SDK failures explicitly mark partial or unavailable data rather than filling in invented zeros. Distinct-file counts can overlap between sessions and are not an office-wide unique-file count or a cost estimate. There is no projected SDK plaque, persistent Signals widget, metrics strip or workspace strip.

Use `npm run typecheck`, `npm test`, and `npm run build` to validate the app.

## Safety and recovery

HTTP is bound to `127.0.0.1` with loopback host, same-origin write, and local browser-cookie checks; do not expose it through a proxy. Every built-in SDK permission request—including shell, reads, commands, writes, and unknown tool kinds—requires **Allow once** or **Deny** in the owning agent's panel; there are no automatic or persisted *shell/write* approvals. The separately attached read-only research tool needs no additional per-file approval once the user explicitly grants that specific repo to that agent. Outstanding human permission requests are denied when the last browser leaves or after 90 seconds. A working directory (even a separate Git worktree) and an instruction to the model are **not OS isolation**: a permitted built-in tool can reach outside its folder, so read paths and commands before allowing. Stronger containment requires a sandbox/container.

Each agent has its own SDK session ID, transcript, desk (or archived state), status, pending permission, persona and recorded working directory in ignored `.local/state.json`; the SDK also stores session history under the signed-in user's Copilot home. Explicitly approved repo roots, cloned snapshot metadata and created worktree locations are stored locally; request prompts and task grants are invalidated on restart. The original single-agent state is migrated in place, keeping its session ID, transcript and root `./sandbox` working directory. In a fresh room, all agents use distinct disposable `./sandbox/agents/<agent-id>/` scratch folders. Prompts go to the GitHub Copilot service under the signed-in account; there is no BYOK, private app RPC, terminal scraping, hosted backend, or analytics added by this app. A restart resumes **each active SDK session** in its own scratch directory or explicitly approved worktree; archived sessions remain recorded but disconnected until restored. An interrupted turn is labeled interrupted, and a failed resume leaves that agent's transcript visible with Retry agent connection rather than silently replacing it. The SDK may not persist an *empty, never-messaged* session; if it reports that exact session missing, the app reinitializes only that empty session under the same ID and says so in the UI. A session containing any messages is never silently replaced.

This no-project prototype has at most **16 active agents**, one per available office desk; archived agents do not occupy desks. Once all are occupied, Add agent clearly says **Office full (16 desks)**, while all existing conversations remain usable. This is not general multi-agent collaboration: agents do not share filesystem authority, coordinate tasks, or spawn other office agents by chat. SDK sessions created by this app are independent; this app **does not connect to, control, observe or infer parent/child relationships among existing Copilot app/CLI sessions**. Project discovery, handoff/merge, worker spawning from chat, account switching, and remote hosting are not implemented. If session creation fails after preparing a scratch folder, the unused marked folder is left untouched for manual inspection rather than deleted.

## Original scene provenance

With the repository owner's explicit permission, the scene was ported from [BranonConor/agentcorp](https://github.com/BranonConor/agentcorp) at commit `724d9031530c81618bf32007fbaa17ac412af7a2`. The copied `agent-inc/game/{animation,lighting,live-layout,simulation,sprite-art,world}.ts`, `agent-inc/app/styles.css`, `agent-inc-live/src/office.tsx`, `agent-inc-live/src/room.ts`, and `agent-inc-live/live.css` originate there. The simulation, art, lighting, layout, room projection, and original styles are reused; `world.ts` adds empty-space selection and `office.tsx` replaces the read-only extension feed with this app's SDK backend and chat. `agent-inc-live/sdk-chat.css` contains the additional conversation/permission UI styling. The original browser extension (`.github/extensions/agent-inc-live`) and its session-activity data source are **not** installed or copied into this app; this app's on-demand usage comes from its own SDK sessions, not the original extension's activity feed. The room remains the original renderer, not an approximation.
